用静态网站做个人主页：我的实践与复盘

🖋️ 林一凡 2026-01-20 6 分钟阅读 复盘 静态网站
🚀

这个网站没有任何后端、没有数据库，也没有复杂的构建流程——就是一套纯 HTML + CSS + 少量 JS。 为什么这么选？值不值？这篇文章是我的完整复盘。

一、为什么选纯静态方案

做个人主页前，我先列了三个硬性要求，静态方案刚好全部满足：

  • 零维护成本：没有服务器要管，没有依赖要升级，几年不碰也不会坏；
  • 极速：全是静态文件，CDN 一挂，全球秒开；
  • 完全可控：每一行代码都属于自己，想改哪里改哪里。

如果只是展示型内容，动态站点的「实时管理」能力大多是伪需求。静态方案省下的精力，值得投入到内容本身。

二、怎么解决「没有后端」的痛点

个人网站最常见的两个动态需求，其实都有轻量解：

需求静态方案成本
联系表单Formspree / Basin 等表单服务免费额度够用
博客评论Giscus（基于 GitHub Discussions）免费
访问统计Umami / 百度统计 等前端统计免费/低成本
站内搜索Pagefind 等静态搜索索引免费

三、踩过的坑与解法

  1. 图片拖慢加载：一开始用了大尺寸原图，首屏 LCP 一度 4s+。 解法是统一压缩 + 现代格式 + 懒加载，现在稳定在 1.5s 以内。
  2. 深色模式刺眼：简单把背景反色并不等于好的深色模式。 正确做法是定义独立的色彩变量，逐个组件验证对比度。
  3. 移动端导航难点：桌面导航直接堆在手机上很难用。 最终用「汉堡菜单」收纳，并把常用操作放在拇指可达区域。
  4. 内容更新靠改代码：文章用 Markdown 维护最舒服。 如果内容变多，可以考虑迁移到 Astro/Hugo 等静态生成器，文章依然是 Markdown，只是多了自动构建。

四、什么时候该升级方案

当出现以下信号时，就该考虑引入框架或静态生成器：

  • 文章超过 20 篇，手动维护列表开始出错；
  • 需要多语言、复杂搜索、图片自动处理；
  • 希望多人协作或接入 CMS 管理内容。

到那时，Astro 会是很好的过渡选择——它能保留「静态优先」的优势，同时给你组件化的能力。 但如果你和我一样，内容不多、追求极致简单，那么纯静态依然是个人主页的最优解。
